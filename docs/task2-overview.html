Single implementation

Return or persist — public API คืน DataFrame; batch script จึงค่อยเขียน Gold ตาม write mode

2. Segmentation rules และ configuration

Ruleค่าเริ่มต้นพฤติกรรมที่มา
Trip startengine_on → Trueเริ่ม trip เมื่อ state เปลี่ยนเข้า ON; แถว ON แรกเป็นจุดเริ่มAssignment rule
Trip endengine_on → Falseรวมแถว OFF เป็นจุดสุดท้ายแล้วปิด tripAssignment rule
Timeoutมากกว่า 10 นาทีปิด active trip เมื่อ gap ระหว่าง record ต่อเนื่องเกิน thresholdsegmentation.gap_minutes
Minimum duration2 นาทีทิ้ง segment ที่สั้นกว่า threshold เป็น noisesegmentation.minimum_duration_minutes
GPS-only fallbackเปิดเมื่อทั้ง stream ไม่มี engine state ให้แบ่งด้วย gap เพื่อรองรับ Grade Bsegmentation.enable_gps_fallback
Open trip at EOFปิดเป็น tripactive segment สุดท้ายใช้ reason stream_endsegmentation.close_open_trip_at_stream_end
เหตุผลที่ต้องมี GPS fallback: Task 1 อนุญาต engine_on=None สำหรับแหล่งข้อมูลที่ไม่มี engine signal หากบังคับ engine transition เพียงอย่างเดียว WDMT จะไม่มี trip เลย จึงใช้ gap fallback พร้อมบันทึก segmentation_method เพื่อให้ผู้ใช้ทราบว่าเป็นผลอนุมาน

6. ข้อสังเกตุ

Trip เป็น Grade B?

Trip ที่ผ่าน minimum duration ไม่มี CAN signal ภายใน segment แม้ dataset รวมจะมีข้อมูล TMT บางส่วน จึงไม่ควรเติมค่า CAN

Harsh counts เป็น null?

ค่าเริ่มต้น grade_a_only=true เพื่อหลีกเลี่ยงการนับ harsh event จาก GPS sampling ที่อาจหยาบหรือไม่สม่ำเสมอ จึงใช้ null เพื่อสื่อว่า “ไม่สามารถประเมินอย่างน่าเชื่อถือ” ไม่ใช่ศูนย์เหตุการณ์

WDMT idle เป็น null

นิยาม idle ต้องมี engine ON และ speed = 0 แต่ WDMT ไม่มี engine state การคืน null

ค่าเฉลี่ยความเร็วสูงแต่ระยะทาง odometer ต่ำในบาง WDMT trip เป็นสัญญาณ data-quality ที่ควรตรวจ upstream เพิ่มเติม ระบบยังคงทั้ง distance_method และค่าความเร็วไว้เพื่อให้ audit ได้ แทนการแก้ข้อมูลเงียบ ๆ
